# Ingame components and provenance

The desktop launcher in `launcher/src` is unchanged.

## Reused original components

- [Polyfrost OneConfig](https://github.com/Polyfrost/OneConfig): `ComposeScreen`,
  `Theme`, `Text`, `Icon`, `IconButton`, `SwitchControl`, and pointer interaction.
  These are linked from the existing OneConfig dependency, not copied and
  reimplemented. Build API: OneConfig 1.2.2. Reference source inspected:
  `7837da24de0f4c9f6d30e37bf771951353092c1b` (upstream 1.2.4); signatures were
  additionally checked against the cached 1.2.2 binary and source artifacts.
  Upstream is LGPL-3.0 with additional terms; see its [LICENSE](https://github.com/Polyfrost/OneConfig/blob/master/LICENSE).
- Minecraft's original `PlayerSkinWidget` supplies the 3D skin preview without
  a world; `InventoryScreen.drawEntity` supplies the equipped player preview
  in a world. Ten animal/helper companions use Minecraft's built-in entity renderers.
- Existing SVG provenance remains in
  `fabricmod/src/main/resources/assets/visualsfabric/ico/ATTRIBUTION.md`.

The module-menu entry now requests the actual OneConfig screen, using the public
`OneConfigUI.createScreen()` API when available and the original public
`OneConfigUIScreen` constructor for the older 1.0.x bundle. The isolated test
instance contains OneConfig 1.0.13; this differs from the build API version.
The complete project-specific settings and cosmetics are linked from its Visual
Client config page. If OneConfig is unavailable, the existing project menu is
retained as a fallback.

The title-screen arrangement remains project-owned, with a Minecraft panorama
and original OneConfig components. It is not an identical copy of PolyPlus.
`textures/logo.svg` reuses the project's launcher `Logo.tsx` geometry.

## Project-owned additions

`FantasyModel` defines the Crystal Dragon, Cloud Spirit, Cuddle Panda, Red Panda,
Penguin and Mochi Bunny geometry using Minecraft's model API. `MiniAccessories`
supplies hats, scarves, shoes and wings for the player Mini-Me. Models share an
original palette texture. The first six Visual cape presets reuse the project's
existing `capeGen.ts`; regenerate them with `fabricmod/tools/generate-capes.cjs`
and the installed Electron runtime. Nine additional designs and the palette are
generated by `fabricmod/tools/generate-extra-cosmetics.py` (Python/Pillow).
The white Monster Energy design is a project-created fan motif, not an official
product or an asset extracted from another client.
No paid Polyfrost cosmetic assets or store entitlements are copied or unlocked.

`CompanionGallery` is a project-owned animated selection grid with illustrated
portraits. Its selected companion appears in the 3D mirror while in a world.
`CompanionMotion` implements bounded cosmetic pathfinding with collision-shape
support in `CompanionTerrain`; it never spawns a gameplay entity. The skin importer
copies local 64-by-64 PNGs into the client's skin library without replacing files.
SkyGlass theme thumbnails are original SVGs; they live in OneConfig's image
namespace because its theme picker resolves preview names there.

`MiniAnimation` supplies allocation-free greetings, head movements and following
hops; `MiniPose` applies the same pose across the immediate and deferred modern
renderers. The deferred player model now applies body yaw before the reflected
model coordinates, matching Minecraft's orientation convention. Sitting offsets
place the hips on the selected shoulder/head instead of above it.

`CosmeticsSync` and `cosmetics-server` connect the project's selections to
authenticated UUIDs. Public multiplayer visibility needs a deployed service;
the service is not automatically hosted by GitHub releases.

## Version boundaries

The launcher can launch versions for which no matching Visual in-game mod
exists. These are different capabilities. The shared modern implementation
targets the existing Fabric 1.21.2–1.21.11 matrix. The 1.8.9 Legacy Fabric module
uses different rendering and Java APIs and does not automatically gain these
features. Other releases, snapshots, Forge and NeoForge are not covered by this
implementation and must not be advertised as having feature parity.
